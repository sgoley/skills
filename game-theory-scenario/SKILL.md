# Game Theory Scenario

## Quick start

1. Confirm the scenario and preparation goal.
2. Run the interview flow in [REFERENCE.md](REFERENCE.md), one question at a time.
3. Build actor cards, a face-up incentive map, pathway tree, and readiness kit.
4. If role simulation is possible, run optional role agents for stress-testing.
5. Deliver preparation output focused on adaptability, not prediction.

## Workflows

### 1) Frame the objective

- Clarify what success means for the user in this scenario.
- Capture non-negotiables, risks, and constraints.
- Set scope: this skill prepares the user for branching outcomes and does not pick a final decision for them.

### 2) Interview and model the scenario

- Gather context timeline and known facts.
- Ask for source artifacts to ground role behavior: emails, chat threads, prior decisions, meeting transcripts, CRM/sales notes, and personal written notes.
- Identify every relevant actor (including observers and hidden influencers).
- Capture each actor's incentives, pressures, fears, leverage, and likely red lines.
- Extract actor-specific signals from artifacts: preferred tone, recurring concerns, decision style, and phrases they often use.
- Create a **Face-Up Card** per actor: likely primary incentive, hidden constraint, and implicit value signal with evidence and confidence.
- Build an uncertainty list: unknowns that could swing the conversation.

### 3) Build pathways and outcomes

- Generate 3-6 plausible conversation pathways (cooperative, neutral, adversarial, mixed).
- For each pathway, map trigger signals, probable moves, likely underlying drivers, and second-order effects.
- Define response options that keep the user's goals intact under each branch.
- Include recovery paths when a branch goes poorly.

### 4) Produce readiness pack (required)

Return:

1. **Scenario Snapshot**: objective, constraints, and stakes.
2. **Evidence Dossier**: available artifacts, reliability, and missing sources.
3. **Actor Map + Face-Up Cards**: actor cards with incentives, pressure points, and inferred implicit drivers.
4. **Pathway Tree**: likely branches with trigger signals and outcomes.
5. **Response Menu**: prepared lines, questions, reframes, fallback moves, and bluff-resistant probes.
6. **Risk and Escalation Plan**: failure modes, damage control, and exit options.
7. **Information Gaps**: what to learn before the real conversation.
8. **Rehearsal Plan**: drills to practice under time pressure.

### 5) Optional multi-agent simulation

- If sub-agents are available, instantiate one role per key actor using prompts in [REFERENCE.md](REFERENCE.md).
- Seed each role with evidence snippets (quotes, prior decisions, transcript moments, written notes) so behavior reflects likely incentives and communication patterns.
- Require each role turn to include: public move, likely incentive/constraint driving it, and evidence-backed confidence.
- Run short turns where each role pursues its own incentives.
- Use outputs to improve readiness artifacts, not to declare a single "predicted" outcome.
